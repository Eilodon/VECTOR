# Decision Policy

## Principle

VECTOR does not ask, “What feels best?”
VECTOR asks, “What does the data justify next?”

## Core decision ladder

| Condition | Interpretation | Action |
|---|---|---|
| No attempts made | Execution gap | Fix execution, do not change strategy yet |
| Attempts made, zero response | Angle problem or weak targeting | Rewrite hook and verify ICP |
| Responses from non-ICP people | ICP drift | Re-check phase 1 assumptions |
| Responses but no interest | Offer mismatch | Tighten problem / offer / CTA |
| Interest but no conversion | Funnel or venue issue | Audit venue, pricing, trust signal |
| Good conversion but low traffic | Channel scale problem | Add growth multiplier or second channel later |
| Repeated failure after threshold | Structural mismatch | Pivot channel or return to ICP |

## Hard gates

### Gate 1 — Do not skip ICP
If the user does not have a plausible ICP, do not move to channel scoring.

### Gate 2 — Do not scale before signal
If the system has not observed a real signal, do not recommend paid scaling.

### Gate 3 — Lock 0→1
At stage 0→1, only one primary channel is allowed.

### Gate 4 — One source of truth
If a file conflicts with the schema, the schema wins.

## Pivot policy

Pivot when one of the following becomes true:

- the same message variation fails repeatedly after reasonable iteration
- the same ICP hypothesis fails across enough attempts
- the venue creates confusion or blocks trust
- the channel is saturated with competitors and the ICP is not present

## Recovery policy

If data quality is too poor to judge:

1. Stop expanding.
2. Rebuild the sample.
3. Clarify the ICP.
4. Repeat the smallest possible experiment.
