# FAQ

## Why English-first?

Because a single canonical language reduces drift, duplication, and formatting inconsistency.

## Why keep Vietnamese notes?

To help the builder read quickly without turning the package into a bilingual copy-paste mess.

## Why schemas?

Because a schema is easier to parse, compare, and audit than free-form prose.

## Why so many platform adapters?

Because each surface stores instructions differently.
A portable system must respect the platform instead of forcing one format everywhere.

## Why is there a recovery mode?

Because weak signals are normal and the framework should help the builder recover fast instead of getting stuck.

## Is VECTOR only for prelaunch products?

No. It works for prelaunch, launched, and weak-growth products. The routing path changes depending on whether there is already signal.

## Does VECTOR replace judgment?

No. It reduces unnecessary guesswork and keeps the process disciplined, but the user still decides the final tradeoffs.

## Why add research and copy as explicit capabilities?

Because many founders need the system to generate evidence and then turn that evidence into usable messaging without switching tools.

## What if the user already has a strong audience?

VECTOR should fast-path toward thesis, venue, and signal rather than spending too much time rediscovering the ICP.

## What if a channel is noisy but promising?

Use the benchmark and drift checks. A noisy channel can still be useful if the right sub-community is clearly present.

## What if the file set feels large?

Use Quick Start first. The system is designed so the user can operate with a minimum entry path and only expand when needed.
